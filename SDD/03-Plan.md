# 金融日报 SDD · 03-Plan 流程层

> 版本：v2.0（Evidence Contract 升级） ｜ 生效日期：2026-08-24 ｜ 归属：finance-digest 技能
> 本文件用 **Evidence Contract** 替代步骤式 SOP：不描述"做什么"，而是定义"交付物、证据、通过标准、失败回滚"。
> 冲突时以 01-Constitution 为准。

---

## 0. 设计理念

**步骤式SOP（旧）**：告诉AI"先做A再做B再做C" → AI照做但不验证结果，错了不知道。
**Evidence Contract（新）**：告诉AI"阶段X的交付物是Y，证据在Z，通过标准是W，失败则回滚到V" → AI每阶段自验，错了自动回炉。

反馈循环（Anthropic 评估器-优化器）：每个Contract未通过→定位问题→修复→重验。上限3次，超过则人工介入。

## 1. C1 采集合同（采集 → 暂存）

| 维度 | 内容 |
|------|------|
| **交付物** | 11个信号的原始采集块（JSON结构，见02-Spec §3），存于工作内存 |
| **证据** | 每个采集块含：信号号、名称、≥1条搜索结果摘要、≥1个来源URL |
| **通过标准** | ① 8组搜索全部执行（R1-R4覆盖，无跳组） ② 11个信号各至少有1个采集块 ③ 每块至少1个URL |
| **失败回滚** | 缺信号→补搜该信号对应组；缺URL→重搜该组；搜索结果<3条→触发降级策略（01-Constitution §6） |

**执行约束**：每轮并发2个搜索，R5为头条交叉验证。关键词从02-Spec §2取，禁止自行编造关键词。

## 2. C2 验证合同（交叉验证 → 可信度标签）

| 维度 | 内容 |
|------|------|
| **交付物** | 每个信号标注最终可信度标签（✅/⚠️/❌），标注依据记录在采集块中 |
| **证据** | ✅已验证→2个独立来源URL（非转载）或1个S级来源；⚠️待确认→1个来源URL；❌→"未找到可靠数据" |
| **通过标准** | ① 头条级信号（LPR/央行/政策）有独立交叉验证记录 ② 无单源B/C级标✅ ③ 同比/环比、实值/预测值标注正确 |
| **失败回滚** | 标签与证据不符→降级标签（✅→⚠️或❌）；头条缺交叉验证→补搜T10；口径混淆→改正后重新标注 |

**裁决优先级**：S级>A级>B级>C级。同级冲突标注差异，以官方为准。

## 3. C3 格式化合同（数据 → 5字段人话）

| 维度 | 内容 |
|------|------|
| **交付物** | 11个信号的5字段完整输出：硬数据表、大白话解读、机构观点、信源区、可信度标签 |
| **证据** | 每个信号的5字段在HTML卡片中可逐一核对；机构观点含真实机构名+分析师名（可搜索验证） |
| **通过标准** | ① 11×5=55个字段位无空缺（❌信号的解读写"未找到可靠数据"） ② 大白话解读无模板套话（禁"综上所述""值得注意的是"） ③ 每条解读含≥1个具体数字或事件 |
| **失败回滚** | 缺字段→补采该字段；有AI味套话→用口语重写（"今天涨了是因为……"）；解读无具体数字→补数字或重写 |

## 4. C4 生成合同（HTML + docx 双格式）

| 维度 | 内容 |
|------|------|
| **交付物** | `每日金融快讯_YYYYMMDD.html` + `每日金融快讯_YYYYMMDD.docx`，存于`YYYY-MM-DD/`目录 |
| **证据** | ① HTML文件存在且可浏览器打开 ② docx文件存在且可Word打开 ③ HTML源码中无`{{`残留占位符 |
| **通过标准** | ① HTML渲染：筛选按钮可点击、暗色模式切换正常、长图导出可用 ② docx无乱码 ③ 页脚含来源汇总表+免责声明5条+统计行 ④ 全部15个占位符已替换 |
| **失败回滚** | 占位符残留→逐个replace补全；HTML渲染异常→读模板重新生成；docx乱码→设PYTHONUTF8=1重跑md_to_js.py→node两步链路；docx生成失败→检查JS文件是否生成成功 |

## 5. C5 校验合同（自检 + 台账同步 + 反馈循环）

| 维度 | 内容 |
|------|------|
| **交付物** | 自检通过记录 + 预测台账更新（新预测登记+到期回测） |
| **证据** | ① 自检清单全部✅（或明确标注降级原因） ② `台账/预测台账.md`第三节有当日新行 ③ 到期预测有回测判定（✅/🟡/❌+四要素） |
| **通过标准** | **数据完整性**：11信号全覆盖、每信号5字段齐全、每数值有URL+等级+时间。**合规性**：无凭记忆数值、无编造来源、无预测混实值、无B/C单源标✅。**格式**：HTML渲染正常、docx无乱码、占位符全替换。**台账**：新预测已登记、到期已回测。 |
| **失败回滚** | 任一不通过→定位具体项→修复→重验对应Contract（C2/C3/C4）。反馈循环上限3次，超过→暂停，告知用户"此处需人工确认"，不硬生成。 |

### 反馈循环执行规则

```
C1不通过 → 补搜 → 重验C1
C2不通过 → 降级标签/补交叉验证 → 重验C2
C3不通过 → 补字段/重写解读 → 重验C3
C4不通过 → 补占位符/重生成 → 重验C4
C5不通过 → 定位属于C2/C3/C4哪个环节 → 修复后重验C5
全部通过 → 交付
循环≥3次仍有问题 → 停止，告知用户
```

修复原则：用正面例证（"正确做法是……"）而非负面否定（"你做错了"）。

## 6. Token 预算执行

| 阶段 | 占比 | 策略 |
|------|------|------|
| 系统(10%) | Constitution+Spec 常驻 | 不膨胀 |
| 用户(15%) | 指令+日期 | 一条消息完成 |
| 检索(40%) | 8组搜索+交叉验证 | 最大投入，禁止冗余 |
| 历史(25%) | 台账摘要+上期要点 | 不读全文，只取摘要 |
| 工具(10%) | 文件读写+HTML | 轻量复用 |

超支预警：单轮>20条→保留Top10+S/A级；检索>50%→缩减政策组深度；重复搜索→合并。

## 7. 异常处理

| 异常 | 处理 |
|------|------|
| 当日无开盘 | 用最近交易日，标注实际日期 |
| 搜索结果<3条 | 简版日报+明示"信息较少" |
| 工具/脚本失败 | 记录报错，读错误修复，3次后人工介入 |
| 来源全不可靠 | 停止生成，说明无法保证数据质量 |
| 用户临时加需求 | 评估影响范围，能并入则并入，不能则告知下期 |
