## 0a. 信号路由分类（Anthropic路由模式）

11个信号按时间敏感性/来源类型/验证深度分6类路由，搜索前先判类别，按类别调策略：

| 路由类 | 信号 | 搜索策略 | 验证策略 | 特殊处理 |
|--------|------|---------|---------|---------|
| **A 实时市场** | A股(1)、汇率(2)、资金面(10) | week过滤 | 双源验证 | 节假日自动降级（不搜无效数据） |
| **B 定期发布** | LPR(3)、国债(4)、央行操作(11) | month过滤 | **头条强制交叉验证** | 非发布日快速跳过（省Token） |
| **C 国际大宗** | 原油(5)、黄金(6)、铜价(7) | week过滤 | 双源验证 | 注意夜盘时差，EIA/CME为S级 |
| **D 海外宏观** | 美联储(8) | week过滤 | 双源验证 | CME FedWatch概率=预测值，强制标注 |
| **E 宏观数据** | CPI/PPI/PMI/社融/M2(9) | month过滤 | 官方兜底 | 标注统计区间，国家统计局为S级 |
| **F 政策速递** | 政策组(第8组) | month过滤 | 单源可接受 | 低优先级，补充性质 |

**路由执行规则**：
1. T1完成后，先判断当天是否有B类信号发布日（如每月20日=LPR），有则全量搜索+交叉验证，无则快速跳过
2. A类信号遇周末/节假日自动降级为"用最近交易日数据"
3. D类（美联储）所有概率数据强制标"预测值"，不得与实值混淆
4. F类（政策组）单源可接受（标⚠️而非❌），不强制双源验证

## 3. Token 预算管理（配合 Context Engineering）

### 3.1 总预算分配（每期日报）

| 环节 | 占比 | 折算token(约) | 用途 |
|------|------|--------------|------|
| 系统 | 10% | ~2K | Constitution/Spec 常驻 |
| 用户 | 15% | ~3K | 任务指令+日期 |
| 检索 | 40% | ~8K | 8组搜索+交叉验证（最大投入） |
| 历史 | 25% | ~5K | 台账摘要+最近一期要点 |
| 工具 | 10% | ~2K | 文件读写/HTML生成 |

### 3.2 省 Token 执行细则

| 策略 | 具体做法 |
|------|---------|
| 搜索空间压缩 | 只搜 Spec 规定的关键词，不加戏 |
| 结果不全文贴 | 搜索返回只提取关键数值/URL/机构观点 |
| 历史压缩 | 台账只读"待验证预测表"+"校准规律"，不读全文 |
| 最近一期 | 只取要点摘要，不读整篇 HTML |
| 复用模板 | HTML 用模板+replace，不重写样式 |
| 一次到位 | 采集时同时记录 URL/时间/等级，避免二次搜索 |

### 3.3 Token 超支预警

- 单轮搜索返回 >20 条 → 只保留 Top10 + S/A级
- 检索阶段累计 >50% → 缩减 T9 政策组深度，保核心组
- 发现重复搜索同一主题 → 合并为一次

## 4. 任务执行铁律（约束所有 T1-T10）

1. **并发限制**：每轮最多 2 个搜索（超出等上一轮完成）
2. **覆盖完整**：8 组必须全跑，禁止跳过（T9 低优先级也要跑，产出政策速递）
3. **数据必联网**：数值型数据禁止凭记忆，必须联网验证
4. **头条复核**：LPR/央行/重大政策必须 T10 独立复核
5. **口径区分**：实际值/预测值、同比/环比严格区分标注
6. **失败重试**：任务失败记录报错→修复→重试（上限3次）→人工介入
